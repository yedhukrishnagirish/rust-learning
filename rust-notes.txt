RUST: OUR LEARNING NOTES
========================
All projects and programs run locally on your Mac.

1. TERMINAL AND RUST TOOLS
What: Terminal accepts text commands. rustc compiles Rust; Cargo manages projects.
Why: Code must be compiled into a program before it can run.
Commands:
  rustc --version      Check the compiler version.
  cargo init           Create a project in the current folder.
  cargo run            Compile and run the project.
  cat src/main.rs      Display your source code.
  cd ~/Downloads/rust-learning
                       Move to our project folder (~ means your home folder).

If Rust is installed but Terminal cannot find it:
  source "$HOME/.cargo/env"
Why: source applies this setup file to the current shell. It adds Rust's tools
folder to PATH, the list of folders Terminal searches for commands.
$HOME means your home folder. This command does not reinstall Rust.

2. PROJECT FILES
Cargo.toml: Project settings, such as name, version and dependencies.
            TOML is the text format used for those settings.
Cargo.lock: Records exact dependency versions for reproducible builds.
src/main.rs: Your application's starting source file.
target/: Generated build files; target/debug/ contains the development program.
Why: Cargo follows this standard layout. Run cargo run from the project folder;
it reads Cargo.toml and knows to use src/main.rs.

3. THE STARTING FUNCTION
What: main is where execution starts. Braces contain its instructions.
Example:
  fn main() {
      println!("Hello, world!");
  }
A semicolon ends this instruction. println! prints text and a newline.

4. VARIABLES AND MUTABILITY
What: A variable names a value. Variables are immutable by default.
Why: Use mut only when a value needs to change.
Example:
  let speed = 5;           // Stays the same.
  let mut position = 0;    // Can change.
  position += speed;      // Reads speed; changes only position.

5. TYPES AND INITIAL VALUES
What: A type specifies the kind of value a variable holds.
Example:
  let mut final_step: i32 = 0;
i32 is a signed 32-bit integer (whole numbers, positive or negative).
Rust can often infer the type, so writing : i32 is not always necessary.

A declaration can omit the starting value:
  let speed: i32;
  speed = 5;
  println!("{}", speed);
The first assignment does not require mut; later reassignments do.
Rust must be able to prove a value is assigned before every read.
Assigning only inside an if or a possibly skipped loop may not guarantee this.
For our final_step counter, start with 0 and use mut.

f64 supports decimal numbers and f64::INFINITY. Integer types have no infinity.
Infinity is a number, not an empty value. You cannot directly assign an integer
variable to an f64 variable; their types differ.

6. PRINTING VALUES
What: Each {} is replaced by the corresponding value, in order.
Why: See what your program is doing.
Example:
  println!("Speed {}, Position {}", speed, position);
Text inside quotes prints literally, including spaces and commas.

7. ARITHMETIC
  speed = speed + 2;    Add 2 and save the result.
  speed += 2;          Same operation, shorter.
  speed = speed * 8;    Multiply by 8 and save the result.
  speed *= 8;          Same operation, shorter.
Why: Update values as a simulation moves forward.

8. CONDITIONS
What: if runs its block when a condition is true; else handles false.
Example:
  if speed > 8 {
      println!("Too fast");
  } else {
      println!("Normal speed");
  }
  >  means greater than.  >= means greater than or equal to.
At speed 8: speed > 8 is false; speed >= 8 is true.

9. LOOPS AND RANGES
What: A for loop repeats its block for each value in a range.
Example:
  for step in 1..=3 {
      println!("Step {}", step);
  }
  1..=3 includes 1, 2, 3.
  1..3  includes 1, 2; stops before 3.
Why: Simulations update repeatedly, one step at a time.
Create position before the loop so it keeps its accumulated value between steps.

10. BREAK VERSUS RETURN
  break;     Exit the loop; continue with code after the loop.
  return;    Exit the current function. Exiting main ends our simple program.
Why: Choose whether to stop movement or leave the entire function.
Example:
  for step in 1..=10 {
      if step > 3 {
          break;
      }
  }
  println!("Loop finished");  // Still runs after break.

11. WARNINGS AND ERRORS
Error: Prevents successful compilation. Fix it before running the new program.
Warning: Compilation can succeed, but Rust points out something worth checking.

Unused variable: You declared a variable without reading it.
  Fix: Use it (for example, print step), or use _step if intentionally unused.
Unused assignment: You overwrite a value before reading that value.
  Fix: Use the initial value or avoid an unnecessary initial assignment.
Naming warning: Use snake_case: final_step, not Steps.
A warning can be ignored temporarily, but understand its cause first.

12. OUR SIMULATION CHALLENGE
Goal: Start at position 0, speed 2. Run at most 10 steps.
Order matters:
  Increase speed by 2 -> limit speed to 8 -> move -> print -> check destination.
Updating position before limiting speed would move with an excessive speed.

Reference solution:
  fn main() {
      let mut position = 0;
      let mut speed = 2;
      let mut final_step: i32 = 0;

      for step in 1..=10 {
          speed += 2;
          if speed > 8 {
              speed = 8;
          }

          position += speed;
          println!("Step {}, Speed {}, Position {}", step, speed, position);

          if position >= 25 {
              println!("Destination reached");
              final_step = step;
              break;
          }
      }

      println!("Reached on step {}, final position {}", final_step, position);
      println!("Simulation finished");
  }

Expected trace:
  Step 1: speed 4, position 4
  Step 2: speed 6, position 10
  Step 3: speed 8, position 18
  Step 4: speed 8, position 26 -> destination reached -> break
Final messages still print. For this example, final_step 0 means the destination
was not reached; the chosen values reach it on step 4.
